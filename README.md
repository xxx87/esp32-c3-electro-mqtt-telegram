## Что делает устройство

Монитор питания: датчик на GPIO2, при стабильном изменении состояния (5 сек) шлёт уведомление в Telegram и публикует `ON`/`OFF` в MQTT. Управление — через Telegram и WiFiManager-портал.

---

## Модули — кто за что отвечает

| Файл               | Роль                                                          |
| ------------------ | ------------------------------------------------------------- |
| `main.cpp`         | Запуск и цикл: Wi‑Fi → MQTT → время → Telegram → OTA → датчик |
| `config`           | Пины, константы, буферы настроек, NVS (`Preferences`)         |
| `wifi_setup`       | Первый запуск / портал настроек, сохранение, factory reset    |
| `mqtt_handler`     | MQTT TLS (порт **8883**), reconnect, publish                  |
| `telegram_handler` | Бот, команды, опрос сообщений                                 |
| `power_monitor`    | Датчик, антидребезг 5 с, рассылка статуса                     |
| `time_utils`       | NTP, часовой пояс Киев, формат длительности                   |
| `ota_handler`      | Имя хоста `ESP32-C3-XXXXXX`, ArduinoOTA                       |

## Настройка нового устройства (пошагово)

### 1. Прошивка

Прошить через PlatformIO (`Upload`). Serial: **115200**.

### 2. Портал WiFiManager

Если сети нет (или после сброса):

1. В эфире появляется точка доступа **`Power_Monitor_Setup`**
2. Подключись к ней с телефона/ПК
3. Откроется страница настроек (обычно `192.168.4.1`)
4. Укажи Wi‑Fi и параметры ниже → Save
5. Таймаут портала — **180 сек**; иначе рестарт и снова AP

Wi‑Fi SSID/пароль — стандартные поля WiFiManager (вверху формы). Остальное — кастомные поля:

| Поле на форме      | Что вводить                           | Пример                                |
| ------------------ | ------------------------------------- | ------------------------------------- |
| **Адреса об'єкта** | Адрес/название объекта (в сообщениях) | `вул. Стадіонна, 6А`                  |
| **Telegram Token** | Токен бота от `@BotFather`            | `123456:ABC-DEF...`                   |
| **Chat ID**        | ID чата (куда слать)                  | `-1001234567890` или `123456789`      |
| **MQTT Server IP** | Хост/IP MQTT-брокера                  | `mqtt.example.com` или `192.168.1.10` |
| **MQTT User**      | Логин MQTT                            | `user1`                               |
| **MQTT Password**  | Пароль MQTT                           | `secret`                              |
| **MQTT Topic**     | Топик для статуса                     | `home/power/stadium`                  |

Важно по MQTT:

- порт в коде зафиксирован: **8883** (TLS)
- в форме порта **нет** — только сервер
- payload: `ON` / `OFF`, retain = true
- clientId = hostname платы (`ESP32-C3-XXXXXX`)
- проверка сертификата отключена (`setInsecure`)

После Save всё пишется в NVS и переживает перезагрузки.

### 3. Telegram

1. Создай бота у `@BotFather` → токен в поле Token
2. Напиши боту `/start`
3. Chat ID: `@userinfobot` / `@getidsbot` или API `getUpdates`
4. В портал — Token и Chat ID **без пробелов**

## Команды Telegram (только свой Chat ID)

| Команда         | Действие                                |
| --------------- | --------------------------------------- |
| `/status`       | Свет есть/нет, длительность, RSSI Wi‑Fi |
| `/reboot`       | Перезагрузка                            |
| `/set_mqtt ...` | Смена MQTT без портала, затем рестарт   |

Формат смены MQTT:

```text
/set_mqtt сервер;юзер;пароль;топик
```

Пример:

```text
/set_mqtt mqtt.example.com;user1;secret;home/power/stadium
```

Разделитель — **точка с запятой `;`**, ровно 4 части. Пробел только после `/set_mqtt`.

## Железо

| Пин        | Назначение                                                                                          |
| ---------- | --------------------------------------------------------------------------------------------------- |
| **GPIO 2** | Датчик питания (`INPUT_PULLUP`, свет = LOW)                                                         |
| **GPIO 9** | Сброс: удерживать **≥ 5 сек** → очистка Wi‑Fi + настроек → рестарт → снова AP `Power_Monitor_Setup` |

Смена состояния света учитывается только после стабильности **5 секунд** (антидребезг).

## Типовой сценарий «с нуля»

1. Прошить плату
2. Подключиться к `Power_Monitor_Setup`
3. Ввести домашний Wi‑Fi
4. Заполнить адрес, Telegram token, chat id, MQTT
5. Save → плата уходит в вашу сеть
6. Дождаться NTP (в Serial: `Time synchronized` / `System ready`)
7. В Telegram: `/status`
8. OTA: устройство видно как `ESP32-C3-XXXXXX`

Если Wi‑Fi/MQTT «забылись» — 5 сек на GPIO9, и настройка как у нового устройства.
